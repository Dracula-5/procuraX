# Dataset strategy and current fixtures

**No licensed public procurement or invoice dataset is bundled or evaluated.** This workspace run avoids external data access. The current synthetic fixtures are intended to validate baseline code paths and reporting, not represent a company or establish model quality.

| Dataset | Source / license | Samples | Features and labels | Generator and limits |
|---|---|---:|---|---|
| `synthetic_procurement_text_v1` | Generated in-repository; no external license | 1,000 | Short description text; 10 spend-category labels | 100 examples/category, deterministic category cue vocabulary plus shared context words; fixed seed 23; stratified 80/20 split. Very separable templates; no multilingual text, abbreviations, class imbalance, realistic noise or temporal drift. |
| `synthetic_spend_amounts_v1` | Generated in-repository; no external license | 525 | Category and positive amount; 25 injected high-side labels | Five categories, 100 normal log-normal examples/category (category-specific log center, shared sigma 0.35) plus five 12x injected outliers/category; fixed seed 29. No vendor, department, time, split-purchase or seasonal features. |
| `synthetic_labeled_invoice_text_v1` | Generated in-repository; no external license | 100 | Labeled invoice text and nine field values | Fixed `Field: Value` lines, randomized amounts and identifiers; seed 31. Does not cover scanned documents, OCR, tables, locale variation or ambiguous real layouts. |
| `synthetic_vendor_preferences_v1` | Generated in-repository; no external license | 720 candidates across 120 queries | Seven normalized vendor features and pairwise-derived top-two preference labels | 80 training queries and 40 evaluation queries, six candidates/query; seeds 41/42. Labels are generated from a fixed hidden utility formula, so the apparent LTR gain is not evidence of real procurement ranking quality. |
| `synthetic_procurement_knowledge_v1` | Generated in the benchmark script; no external license | 32 query/document pairs | Exact topical term retrieval | Each query repeats the target document's distinctive words; perfect retrieval only tests metric plumbing. |
| Procurement workflow demo data | Generated by the demo seed script; fictional | Demo-specific | Requests, vendors, budgets, approvals | Product walkthrough data only. It is not model training/evaluation data or real customer activity. |

Reproduce synthetic baseline smoke results from `backend/` with:

```powershell
python -m app.scripts.benchmark_spend_classifier
python -m app.scripts.benchmark_amount_anomaly
python -m app.scripts.benchmark_invoice_text
python -m app.scripts.benchmark_vendor_ranking
python -m app.scripts.benchmark_rag_retrieval
```

Use the outputs in [synthetic_baseline_results.json](../reports/synthetic_baseline_results.json) as the recorded run. Scores are perfect because the generated tasks are intentionally simple. They demonstrate deterministic execution and metric plumbing; they must not be used for deployment decisions or resume claims about real accuracy.

## Data still needed

- A lawful, representative spend-description dataset with category labels and a documented license for a public benchmark; a comparable embedding/transformer model and evaluation are also absent.
- Tenant-approved historical purchase/vendor outcomes for vendor ranking, with point-in-time features to prevent target leakage.
- Lawfully usable invoice files with field-level ground truth and a document license; the environment has no OCR engine or invoice corpus.
- Time-ordered transaction history with reviewed anomaly labels, including false alerts and normal edge cases.
- Procurement policy documents with tenant access controls are supported as versioned plain text. Representative retrieval queries and human-judged relevance labels are still required for credible Recall@K/MRR evaluation; semantic embeddings and reranking remain unimplemented.

For each acquired dataset, record source URL, license, retrieval date, sample count, schema, label process, exclusions, PII handling, train/test split, known bias and retention terms before using it.
